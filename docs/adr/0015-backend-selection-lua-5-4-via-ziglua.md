# ADR-0015 — Backend selection: Lua 5.4 via ziglua.

*Context:* G13 requires, before any product code, that the chosen backend (a) stops a `while true` guest at its deadline without killing the process and (b) fails a memory-capped guest catchably. All three backends were built into Zig 0.17.0 binaries and measured on the target host (4 vCPU, Ubuntu 24.04; QuickJS under `taskset -c 0`, so its times are upper bounds).
*Evidence:*

| | Lua 5.4.9 (ziglua @89b445c) | Janet 1.40.1 | QuickJS-NG @e22ce4d |
|---|---|---|---|
| Builds into Zig 0.17 | yes (394 s cold; `--release=fast`) | yes (72 s; 4-line build.zig; vendored `janet.c` has no `main`) | yes (68 s; **`@cImport` no longer exists** → `b.addTranslateC` + `@import("c")`) |
| Fresh VM + chunk loaded | **19.6 µs** median of 18 run-medians, p95 43.6 | 44.9 µs (`janet_table_clone` + load; `janet_core_env` is memoised) | 288.9 µs runtime+context; 300 µs with bytecode |
| Call through the host boundary | 1.13 µs via ziglua's wrapper; **0.11 µs** raw C API | 0.69 µs identity; 1.16 µs table build | 0.50 µs bare; 0.76 µs with arg object + result |
| RSS per idle VM | **18.6 KB** (stdlib opened), 6.8 KB bare | 41.0 KB per cloned env (no per-VM heap) | 162.7 KB |
| Memory cap | **hard and catchable** — `LUA_ERRMEM` at 1 047 986/1 048 576 B, state reusable afterwards | **soft only** — allocator-triggered interrupt, 640 B overshoot; returning NULL hits `JANET_OUT_OF_MEMORY` → `exit(1)`, process dead | hard, `InternalError: out of memory`, `JS_IsUncatchableError`; ~128 KiB practical floor |
| Preempt a runaway guest | **yes** — count hook, 50.016 ms, 3.7k–8.1k hook calls, state reusable | **yes, same-thread only** — POSIX timer signal → `janet_interpreter_interrupt`, 50 ms exact; a cross-thread watchdog silently does nothing (`janet_vm` is thread-local) | **yes** — 50.07 ms; but one long native builtin (`'x'.repeat(1e8)`) ignores it for 636 ms |
| Host-driven GC and teardown | `lua_gc(LUA_GCCOLLECT)` at any time | **`janet_collect()` aborts outside `janet_continue`** (null `root_fiber`); GC only from inside a fiber | `JS_RunGC` at any time |

*Decision:* Lua is the MVP backend. It is not the fastest to start (Janet is) and not the most familiar (QuickJS is); it wins on the three properties a long-running multi-tenant host cannot fake: a **hard, catchable memory ceiling** that matches `--vm-budget-mb`; **host-driven GC and teardown**, so evicting a cell actually reclaims its memory; and **no per-thread global VM state**, so cells are independent objects rather than clones hanging off one memoised core. It is also the cheapest: 64 resident cells cost 1.2 MB versus 2.6 MB (Janet) and 10.4 MB (QuickJS), with a 15× faster cold start than QuickJS. QuickJS-NG is designated backend #2 for post-MVP — both limits are real, and JS is the language uploaders already know; it is not MVP because of 163 KB per idle cell, the uncatchable OOM, the native-builtin preemption blind spot, and the riskiest C ABI of the three. Janet passes G13 and is rejected on operational fit, not on ability: soft-capped memory whose hard failure is process death, and no way to collect its garbage from the host, are both disqualifying for a service that evicts cells. It can return as an experimental backend if the architecture ever moves to one cell per OS process — where its thread-local VM and memoised core stop being constraints.
*Consequences:* `-Dvm=lua` is the default; `caps.preempt` and `caps.hard_mem_limit` are true and printed by `--version`; G11 asserts in-place kill. The guest call boundary is one string in and one string out precisely because the wrapper costs 10× the raw C API — keep crossings coarse. `luaL_openlibs` is most of the 19.6 µs; opening a curated subset (base/string/table/math) is the expected optimisation and doubles as sandboxing — measure it before claiming it.
*Correction (recorded, not edited away):* an earlier revision of this ADR declared Janet disqualified by G13 on the strength of a cross-thread watchdog experiment. That experiment was invalid — `janet_vm` is thread-local, so the watchdog set a flag on its own VM and the interpreter never saw it. The Janet spike found the working mechanism (same-thread POSIX timer signal) and this ADR now rests on the corrected data.

_Status: accepted. Immutable; supersede rather than edit._
